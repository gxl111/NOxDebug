# Modbus 从站 — 地址与寄存器映射表

本文档与 `modbus_slave.h` / `README.md` 第 5 节一致，便于主站（HMI/SCADA）对照。**保持寄存器**为 **4xxxx**（功能码 **03H** 读、**06H** 写单字、**10H** 写多字）。请求 PDU 中的**起始地址** = 表内「PDU 偏移」（从 **0** 起，即 *逻辑地址 − 40001*）。

**符号列**：为 `modbus_slave.h` 中宏名的**后缀**（已去掉前缀 `SLAVE_REG_`）。完整 C 宏为 **`SLAVE_REG_<符号>`**（例：`NOX_OUTPUT` → `SLAVE_REG_NOX_OUTPUT`）。

**约定**

- **Float**：IEEE 754 单精度，**大端**，占 **2 个连续寄存器**（先高 16 位字、后低 16 位字）。
- **uint16**：单寄存器。
- **03H 单次最多读 125 个寄存器**；本机共 **145** 字（40001–40145），需分帧时分段（例如先 40001×125，再 40126×20）。
- **10H 单次最多写 25 个寄存器**（受从站 60 字节接收缓冲限制）；写 Float 时必须从高字地址开始一次写完整 2 个寄存器。06H 不支持写 Float 高/低字。
- **阀门互锁**：同一路正常抽气阀与反吹阀互斥；打开校准阀时，同路正常抽气阀和反吹阀都会保持关闭。同路非反吹、非校准时，直接写正常抽气阀为 1 会进入手动抽气覆盖，可绕过自动抽气的 `0x1FF` 条件；写 0、反吹或校准会清除覆盖。直接写反吹阀为 1 会被策略视为该路正在反吹；反吹阀关闭后，该路还会按 `BLOW_RECOVERY_DELAY_S`（默认 10 s）继续保持切阀前数据并暂不参与输出选择。自动周期和 `BLOW_CMD` 启动反吹时会检查其它通道，并同步写对应 `VALVE_BLOW=1`；直接写多个反吹阀寄存器时，代码只保证同路互锁，不做跨通道手动互锁。

## 工作模式寄存器（40012 / `WORK_MODE`）

- **保持寄存器地址**：**40012**（PDU 偏移 11）。源码：`g_tVar.work_mode`；头文件宏 `SLAVE_REG_WORK_MODE`，表内符号 `WORK_MODE`。
- **README.md §5.1 公共寄存器表**里该行的名称列为 **P34**，与本寄存器为同一地址；**P01、P35** 等同理，均为该节对各 4x 寄存器的命名列，便于与说明书/接口表对照。
- **功能**：选择三路 NOx/O2 **合成输出策略**——**0** 单路目标、**1** 主备、**2** 融合（实现见 `nox_channel.c`，说明见 README §6.6）。上电默认 **1（主备，ch0 为主）**（`NOx.c` `Register_Init`）。
- **读 03H**：`modbus_slave.c` 仅返回 **`work_mode & 0xFF`**（值为 **0/1/2**），**不包含**高字节中的通道选择；要知道当前实际选用的传感器路，请读 **40013（P35，`OUTPUT_SENSOR`）**。
- **写**：见 §1.1；单路/主备时通道选择在 **`value & 0x0300`**（与 README 中 0/256/512、1/257/513 写法一致）。单路和主备都会在目标/主通道反吹、处于恢复保持期或无效时临时切到其它已稳定且有效通道，实际来源以 **40013(P35)** 为准。

### 1.1 40012 / `work_mode` 写入编码

| 模式（写入字低字节） | 完整写入值示例（十六进制） | 含义 |
|----------------------|----------------------------|------|
| **0** 单路 | `0x0000` / `0x0100` / `0x0200` | 通道 0 / 1 / 2 作为目标通道；目标反吹、处于恢复保持期或无效时会临时使用其它已稳定且有效通道 |
| **1** 主备 | `0x0001` / `0x0101` / `0x0201` | 通道 0 / 1 / 2 为**主**（同上，低字节为 1 + `0x0300` 选路） |
| **2** 融合 | `0x0002` | 至少两路有效且不在反吹/恢复保持期时平均；不足两路有效时降级主备逻辑；**不写高字节通道**（源码仅 `work_mode = 2`） |

与 `modbus_slave.c`：`mode==0||1` 时 `g_tVar.work_mode = (value & 0xFF) | (value & 0x0300)`；`mode==2` 时 `g_tVar.work_mode = 2`。写完后在 **`NOxReceive` 下一策略周期（约 50 ms）** 生效。
