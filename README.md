## 1. 概述

**NOxDebug** 是基于 **STM32F103RCT6** 的嵌入式应用，作为 **NOx（氮氧化物）传感器监控与调试节点**。通过 **J1939/CAN** 接收传感器数据，支持**单路、双路或三路**传感器（可配置通道数），对每个传感器进行**两段线性标定**，驱动每通道的**正常抽气、反吹、校准**三类阀门，并通过 **Modbus RTU** 暴露读数和参数；同时作为 Modbus **主机**，将 **4–20 mA** 输出值写入外部电流输出模块。

### 1.1 主要功能概览

| 功能 | 说明 |
|------|------|
| **传感器接入** | 支持 2 或 3 路 J1939 传感器：**ch0** = CAN1 SA 0x52（出口）、**ch1** = CAN1 SA 0x51（入口）、**ch2** = CAN2（MCP2515）SA 0x52。通道数由 `app_config.h` 中 `NOX_SENSOR_COUNT` 决定（当前为 3）。 |
| **工作模式** | 寄存器 **P34（40012）**：**0** = 单路目标（高字节选通道 0/1/2）、**1** = 主备（高字节选主通道）、**2** = 融合（多路有效时取平均）。默认**主备**。 |
| **输出** | 单一 **P01/P02/P07** 与 **4–20 mA** 由当前策略（单路/主备/融合）决定；**P35** 只读，表示当前实际输出来自哪一路、融合或故障。 |
| **标定** | 每传感器独立：NOx / O₂ 各 3 点、两段线性；标定触发与点选择在各传感器块内，无全局“标定目标”。标定结果可存片内 Flash。 |
| **Modbus 从站** | USART1/RS485，供 HMI/SCADA 读写保持寄存器。 |
| **Modbus 主站** | UART5/RS485，周期将 4–20 mA 码写入外部从站并读回校验。 |
| **阀门** | **9 路**继电器 **J1–J9**（3 个一组）：每传感器 **正常抽气检测、反吹、校准**；由**保持寄存器**（40053–40055、40095–40097、40137–40139）控制。正常抽气阀与反吹阀互斥；校准阀打开时禁止同路抽气和反吹。 |
| **显示** | OLED 显示 S1/S2/S3 实时 NOx、O₂、状态及当前输出、运行时间。 |

### 1.2 两个 SA 0x52 为何不冲突

系统中存在两个使用源地址 **0x52** 的传感器（ch0 与 ch2），**不会冲突**：

- **物理上为两条 CAN 总线**：第一路为片载 CAN（PA11/PA12），接 ch0、ch1；第二路为 MCP2515 的 CAN，接 ch2。两总线隔离。
- **软件按“接收自哪路 CAN”区分**：片载 CAN 收到的按 SA 得到 ch0 或 ch1；MCP2515 收到的 0x18F00F52 固定入队为 ch2。通道号由“哪一路 CAN 收到”决定，两个 0x52 分别对应 ch0 与 ch2。

## 2. 硬件

### 2.1 总体

| 项目 | 说明 |
|------|------|
| **MCU** | STM32F103RCT6（LQFP64），72 MHz，HSE 8 MHz + PLL×9 |
| **CAN** | 250 kbps，J1939；片载 CAN 连接 ch0、ch1 传感器 |
| **USART1** | **Modbus 从站**，RS485，默认 **115200** 波特（可由 SD 卡 `config.txt` 覆盖） |
| **UART5** | **Modbus 主站**，RS485，**9600** 波特，接 4–20 mA 输出模块 |
| **I2C1** | OLED（PB6 SCL，PB7 SDA） |
| **SPI1** | SD 卡（FATFS）；可配置波特率等 |
| **SPI2 + MCP2515** | 第二路 CAN：PB13 SCK、PB14 MISO、PB15 MOSI，PC10 CS、PC11 INT；接 ch2（SA 0x52） |
| **阀门继电器 J1–J9** | S1：J1=PA4（正常抽气）、J2=PA3（反吹）、J3=PA1（校准）；S2：J4=PA0、J5=PC3、J6=PB3；S3：J7=PB4、J8=PB5、J9=PB8 |
| **传感器使能继电器 JC1–JC3** | JC1=PC0（S1）、JC2=PC13（S2）、JC3=PB9（S3）；由上电寄存器 40014/40056/40098 驱动 |

引脚与标签在 CubeMX 工程（`NOx_RCT6.ioc`）及 `main.h` 中定义。

### 2.2 SPI 转 CAN（MCP2515）— 第二路 CAN 与 ch2

- **SPI2**：PB13 SCK、PB14 MISO、PB15 MOSI；**片选** PC10（MCP2515_CS），**中断** PC11（MCP2515_INT）。
- **ch2**：J1939 扩展 ID **0x18F00F52**（PGN F00F，SA 0x52），250 kbps，8 字节载荷；加热命令 **0x18FEDF55** 由本机在第二路 CAN 上周期发送。
- 初始化时设置滤波仅接收 0x18F00F52；`NOxReceive` 中轮询 MCP2515 接收并压入 J1939 队列，通道索引 2。

## 3. 软件架构

- **HAL** + **FreeRTOS**（CMSIS-RTOS v2）。
- **任务**：
  - **defaultTask**：占位。
  - **NOx_Default**：标定轮询、报警、三路反吹逻辑、运行时间、OLED 刷新。
  - **ModBus_Slave**：Modbus 从站轮询（USART1）、寄存器与 Flash 访问。
  - **NOx_Receive**：出队 J1939 帧（带通道索引 0/1/2），轮询 MCP2515 收 ch2；更新每通道数据，应用工作模式策略，更新 P01/P02/P07 及每传感器实时寄存器，填充 4–20 mA 缓冲，发送 CAN 加热命令（片载 CAN + MCP2515）。
  - **ModBus_Host**：周期将 4–20 mA 数据写入外部从站（UART5）并 03H 读回校验。
- **定时器**：TIM6（HAL 节拍）、TIM7（10 ms 基准）、TIM2/TIM3（Modbus 从站/主机 RX 超时）。

应用代码主要在 **USER/**；传感器数学与默认值在 **nox_sensor** 与 **app_config.h**。

| 模块 | 职责 |
|------|------|
| **NOx.c** | J1939 处理（每通道）、任务入口、策略、寄存器/Flash 初始化、MCP2515 收发与加热帧。 |
| **nox_channel** | 每传感器通道状态与参数；`NoxChannel_UpdateFromCan`、`NoxChannel_GetCurrentOutput`；支持 2/3 路。 |
| **blowback** | 反吹定时与命令；自动反吹时驱动 J2/J5/J8（S1/S2/S3 反吹阀），反吹结束关闭反吹阀并恢复正常抽气条件。 |
| **calibration** | 每传感器 NOx/O₂ 标定（各块内触发与点选择）、斜率/截距；`Calibration_Init`。 |
| **alarm** | 报警阈值（P12/P13）与当前输出（P01/P02）比较。 |
| **J1939** | CAN 接收队列（带通道索引）、片载 CAN 发送加热命令。 |
| **mcp2515_spi_can** | MCP2515 初始化、收发、滤波。 |
| **modbus_slave** | 从站、寄存器映射（公共 + S1/S2/S3 块）、Flash 读写。 |
| **modbus_host** | 主站、4–20 mA 写入/读回（10H + 03H）。 |

## 3.1 控制逻辑速览

如果只是现场调试，不需要先把 40001–40145 全部背下来。先按下面顺序看：

1. **当前系统输出**：读 **40001–40005**，即 P01 NOx、P02 O2、P07 输出状态。P07=511(0x1FF) 表示当前输出源正常。
2. **输出来自哪里**：读 **40012/40013**。40012 只读回模式低字节（0 单路、1 主备、2 融合），40013(P35) 才是当前实际来源：1=S1/ch0，2=S2/ch1，3=融合，4=S3/ch2，0=故障。
3. **每路传感器是否健康**：读各块的实时值和状态：S1 **40015–40019**，S2 **40057–40061**，S3 **40099–40103**。状态 bit9(0x0200) 置位表示该路 CAN 静默超时，策略会把该路当作无效。
4. **反吹是否正在接管气路**：读各块 **BLOW_STATUS/BLOW_CD**（S1 40050/40051，S2 40092/40093，S3 40134/40135）。反吹中该路不参与输出选择，且正常抽气阀会被强制关断。
5. **阀门实际控制口**：正常抽气/反吹/校准阀分别在每块最后 3 个寄存器：S1 **40053–40055**，S2 **40095–40097**，S3 **40137–40139**。

整体控制链路是：**CAN 帧更新通道状态** → **通信超时判定** → **P34 策略选择 P01/P02/P07 与 1 号 4–20 mA** → **三路传感器原始输出写入 2 号 6 路 4–20 mA** → **标定/报警/反吹周期任务更新参数和阀门** → **Modbus 从站暴露镜像寄存器**。

## 4. 通信

### 4.1 J1939 / CAN

- **角色**：从**多路**传感器接收 NOx 帧；向**两路 CAN**（片载 + MCP2515）发送同一加热命令。
- **滤波**：片载 CAN 接受 SA **0x52**（ch0）、**0x51**（ch1）；MCP2515 接受 **0x18F00F52**（ch2）。每帧带通道索引入队。
- **接收载荷（8 字节）**：Data[0–1] NOx 原始；Data[2–3] O₂ 原始；Data[4] 状态；Data[5] 加热；Data[6–7] 故障码。
- **加热命令**：ID `0x18FEDF55`，Byte7 启动码（如 0x55），片载 CAN 与 MCP2515 均发送。

### 4.2 Modbus 从站（USART1，RS485）

- **默认**：地址 **1**（`MODBUS_SLAVE_DEFAULT_ADDR`），波特率 **115200**（`MODBUS_SLAVE_DEFAULT_BAUD`）；统一在 `app_config.h` 配置，也可由 SD 卡 `config.txt` 覆盖。
- **功能码**：03H（读保持）、06H（写单寄存器）、10H（写多寄存器）。
- **数据格式**：保持寄存器大端；浮点占 2 个连续 16 位寄存器。

### 4.3 Modbus 主站（UART5，RS485）

- **默认**：波特率 **9600**（`MODBUS_HOST_DEFAULT_BAUD`），统一在 `app_config.h` 配置。
- **1 号模拟量模块**：地址 **0x01**，写策略输出 NOx/O₂；**10H** 从 `0x000A` 起写 2 个寄存器，再用 **03H** 读回校验。
- **2 号 6 路模拟量模块**：地址 **0x02**，从 `0x000A` 起连续写 6 个寄存器：S1 NOx、S1 O₂、S2 NOx、S2 O₂、S3 NOx、S3 O₂，并读回到 40140–40145。
- **读回开关**：`AO_MODULE_READBACK_ENABLE=0` 时只写不读，`10H` 应答即表示模块已接受寄存器；本机 40010–40011、40140–40145 仍同步为当前发送值。改为 1 时会额外用 `03H` 读回校验。
- **2 号地址配置**：`app_config.h` 中 `AO_MODULE_SLAVE_2_ADDR_CONFIG_ENABLE` 默认为 0。需要把新模块从默认 1 改地址时，只接这块新模块，把 `AO_MODULE_SLAVE_2_ADDR_CONFIG_TO` 改成目标地址（如 2 或 3），再把使能宏改为 1 运行一次；模块站号寄存器为 `0x0032`。配置模式只发送一次 06H 写站号命令，严格校验回包后停止正常轮询，`g_ao_addr_config_status` 为 1 表示成功、2 表示失败。写完后给模块重新上电，并把使能宏改回 0。正常轮询地址 `AO_MODULE_SLAVE_2_ADDR` 会跟随这个目标地址。

## 5. Modbus 寄存器映射

布局：**公共**（40001–40013）→ **传感器 1 块**（40014–40055）→ **传感器 2 块**（40056–40097）→ **传感器 3 块**（40098–40139）→ **6 路 4–20 mA 镜像**（40140–40145）。每传感器块 **42 个寄存器**（39 + 3 个阀门），结构相同；块首为上电寄存器（R/W），块末为**三个阀门**（正常抽气、反吹、校准），写寄存器即驱动 J1–J9。

### 5.1 公共寄存器（40001–40013）

| 地址 | 名称 | R/W | 说明 |
|------|------|-----|------|
| 40001–40002 | P01 | R | 当前 NOx（ppm），float，策略输出 |
| 40003–40004 | P02 | R | 当前 O₂（%），float，策略输出 |
| 40005 | P07 | R | 当前输出状态字（9 位），0x1FF=正常 |
| 40006–40007 | P12 | R/W | NOx 高报警（ppm），float |
| 40008–40009 | P13 | R/W | O₂ 低报警（%），float |
| 40010 | P22 | R/W | 4–20 mA NOx 码 |
| 40011 | P23 | R/W | 4–20 mA O₂ 码 |
| 40012 | P34 | R/W | **工作模式**。读：只返回低字节 0/1/2（单路/主备/融合），不读回高字节选路。写：低字节=模式；单路时高字节 **0/256/512** = ch0/ch1/ch2；主备时高字节 **0/256/512** = ch0/ch1/ch2 为主（完整写入值分别为 1/257/513）。 |
| 40013 | P35 | R | **当前实际输出源**（只读）：0b01=S1/ch0，0b10=S2/ch1，0b11=融合，0b100=S3/ch2（第二路 CAN），0b00=故障。 |

### 5.4 状态字（P07、各传感器状态）

**低 9 位**为 J1939 推导的状态；**第 9 位（数值 0x0200）** 为固件通信超时标志。状态字出现在 P07（40005）与各传感器状态寄存器（40019、40061、40103）。  
**511（0x1FF）** = 传感器侧全部条件正常，且**未**通信超时（bit9=0）。

| 位 | 置位（1） | 清除（0） |
|----|-----------|-----------|
| 0 | O₂ FMI 正常 | O₂ 故障或 FMI 非“无错误” |
| 1 | NOx FMI 正常 | NOx 故障或 FMI 非“无错误” |
| 2 | 加热 FMI 正常 | 加热故障 |
| 3 | 加热激活 | 停止/预热 |
| 4 | 电源在范围 | 供电超范围 |
| 5 | 传感器达温 | 未达工作温度 |
| 6 | O₂ 信号有效 | O₂ 不稳定/无效 |
| 7 | NOx 信号有效 | NOx 不稳定/无效 |
| 8 | 保留（固件恒置位） | — |
| **9** | **通信超时：超过 `NOX_CAN_SILENCE_TIMEOUT_MS`（`app_config.h`，默认 2000 ms）未收到该路 J1939 NOx 报文**（断线、掉电、CAN 故障等） | **近期已收到该路报文** |

通信超时置位时，该路 **`valid`=0**，不参与主备/融合的有效判定；状态字中 J1939 各位不再反映实时报文（固件置为 **0x0300**，即 bit8+bit9）。恢复收帧后由下一帧重新计算状态。

## 6. 使用说明

### 6.1 编译与烧录

- 用 Keil µVision 打开 **MDK-ARM/NOx_RCT6.uvprojx**，编译（F7），ST-Link 烧录（F8）；也可使用 STM32CubeProgrammer。

### 6.2 首次上电

- 上电后从**片内 Flash** 加载参数（若曾保存）；若 Flash 为空则使用 **app_config.h** 与 **Register_Init** 的默认值。
- **出厂写 Flash**：在 **app_config.h** 将 **FACTORY_FLASH_PROGRAM_ON_BOOT** 设为 **1**，编译、烧录、上电一次；固件在 **Register_Init** 之后执行 **FactoryFlash_ProgramDefaults()** 写入默认标定，该次启动不 Load。然后改回 **0** 并重新编译烧录，进入正常使用。若一直为 1，每次上电都会覆盖用户标定。
- Modbus 从站：USART1，默认 115200、地址 1；HMI/PC 需一致。可选：SD 卡 **config.txt** 覆盖波特率（键名见 SD 模块 **handleConfig()**）。

### 6.3 读取 NOx 与 O₂

- **P01/P02/P07**：当前策略输出，Modbus 03H 读。
- 各传感器块：块首为上电，随后实时 NOx、O₂、状态（S1：40015–40019，S2：40057–40061，S3：40099–40103）。P07=0x1FF 表示当前输出源正常。

### 6.4 标定（每传感器、3 点两段）

- 无全局 P53；写哪一传感器块的标定触发即对该传感器生效。
- **NOx（S1）**：40044 点选择 0/1/2；40036–40043 设点 2/3 的 NOx、O2 参考值；通标准气稳定后写 **40045=0x0001** 执行一步（成功 0x000F，失败 0x0005）；写 **40045=0x0002** 恢复默认（成功 0x0010）。S2 使用点选择 **40086**、触发 **40087**；S3 使用点选择 **40128**、触发 **40129**。
- **O2（S1）**：40047 点选择 0/1/2；写 **40046=0x0001** 执行一步，写 **40046=0x0002** 恢复默认。S2 使用点选择 **40089**、触发 **40088**；S3 使用点选择 **40131**、触发 **40130**。
- 标定成功或出厂编程时会调用 **InternalFlash_Write**；S1/S2/S3 的反吹间隔/时长一并写入 Flash。反吹三等分相位由 **BLOW_PHASE_DIVISOR** 固定，不存 Flash。

### 6.5 反吹与阀门控制

- **反吹间隔/时长/命令**（每传感器）：S1 为 40048–40052，S2 为 40090–40094，S3 为 40132–40136。命令：0 无操作；1 触发一次；2 触发并重置周期；3 或 0xFFFF 停止。间隔 0 或 0xFFFF 表示停止周期反吹，但不禁止 `BLOW_CMD=1/2` 手动触发本次反吹。
- **阀门**：写 **40053/40054/40055**（S1）、**40095–40097**（S2）、**40137–40139**（S3）即驱动 J1–J9（0=关，1=开）。正常抽气阀与反吹阀互斥：直接写反吹阀为 1 会关闭同路正常抽气阀，并被策略视为该路正在反吹；直接写正常抽气阀为 1 会关闭同路反吹阀。自动周期和 `BLOW_CMD` 反吹通过统一阀门入口打开 **J2（S1）/J5（S2）/J8（S3）**，同时把对应 `VALVE_BLOW` 寄存器置 1；结束后关闭反吹阀并恢复正常抽气条件。
- **自动/手动抽气**：`Modbus_AutoSuctionValvesUpdate()` 每 100 ms 检查各路状态。未手动覆盖时，只有传感器状态字为 **0x1FF**、非反吹、校准阀关闭，正常抽气阀才会自动置 1，否则置 0；状态翻转有 **SUCTION_VALVE_DEBOUNCE_MS**（默认 1000 ms）防抖。同路非反吹、非校准时，手动写正常抽气阀为 1 会立即打开并进入手动覆盖，不要求 `0x1FF`；手动写 0、进入反吹或打开校准阀都会清除该覆盖。
- **校准联锁**：某路校准阀打开时，该路视为标定占用。固件会停止该路反吹定时器，清除该路反吹命令，强制关闭该路正常抽气阀与反吹阀；该路周期反吹和手动反吹命令都不会执行。关闭校准阀后，自动抽气和周期反吹按原策略恢复。
- **共享周期**：三路传感器共享一个反吹周期；写任意一路 `BLOW_INT` 都会同步到 S1/S2/S3。刚上电后不会立即反吹，S2 在 1/3 周期触发，S3 在 2/3 周期触发，S1 在第 1 个完整周期触发；之后三路继续按同一相位循环。自动反吹和 `BLOW_CMD` 启动反吹时会检查其它通道，已有通道反吹则跳过本次启动；`BLOW_INT=0/0xFFFF` 只停止周期触发。
- **数据保持**：某路反吹阀打开前即锁存切阀前最后值；反吹期间以及反吹结束后的抽气恢复延时内，CAN 接收时间仍刷新，但该路 raw/NOx/O2/state/valid 保持不变。恢复延时由 `BLOW_RECOVERY_DELAY_S` 配置，默认 10 s；这段时间抽气阀可以恢复打开，但输出策略继续避开该路，避免刚恢复抽气时的非稳定读数污染 P01/P02/P07。

### 6.6 工作模式（P34）

- **单路（0）**：高字节 0/256/512 = ch0/ch1/ch2 作为目标通道。若目标通道正在反吹、处于恢复保持期或无效，固件会临时使用其它已稳定且有效的通道；若全部无效，则 P35=0（故障），P01/P02 保留目标通道最近值/默认值，P07 使用该通道状态。
- **主备（1，默认）**：完整写入 1/257/513 = ch0/ch1/ch2 为主。优先主通道；主通道反吹、处于恢复保持期或无效时，切到其它已稳定且有效通道；全部无效时 P35=0。
- **融合（2）**：多路有效且都不在反吹/恢复保持期时 NOx/O2 取平均，P35=3；不足两路有效时降级为主备选择（默认从 ch0 开始找有效通道）。
- **读回约定**：读 40012 只返回模式 0/1/2，不返回高字节目标/主通道；现场判断实际输出源请读 40013(P35)。上电默认 P34=1（主备，ch0 为主）。写 40012 在下一策略周期（约 50 ms）生效。

### 6.7 报警与 4–20 mA

- **P12** NOx 高报警、**P13** O₂ 低报警；**Alarm_Update()** 中与 P01/P02 比较，可扩展继电器或报文。  
- 4–20 mA：策略结果经 **NoxSensor_To4_20mA** 填入 **electricity_data_buf**，Modbus 主机经 UART5 以 10H 写入外部模拟量模块；是否 03H 读回由 `AO_MODULE_READBACK_ENABLE` 控制。

### 6.8 修改默认值

- **app_config.h**：统一放编译期/现场调试配置，包括 `NOX_SENSOR_COUNT`、`NOX_SENSOR_SA_LIST`、默认斜率/截距、标定 Y 值、报警阈值、反吹默认间隔/时长、反吹后抽气恢复延时 `BLOW_RECOVERY_DELAY_S`、BLOW_PHASE_DIVISOR、4–20 mA 满量程、Modbus 从站默认地址/波特率、Modbus 主站波特率/应答超时/重试/轮询间隔、模拟量模块地址/读回/地址配置开关、J1939 加热 ID/载荷、`FACTORY_FLASH_PROGRAM_ON_BOOT`、`SENSOR_POWER_GPIO_ENABLE`。
- **Register_Init()**（NOx.c）：工作模式默认 `g_tVar.work_mode = 1`（主备）。  
- **modbus_slave.h / modbus_host.h**：保留协议地址、寄存器映射、缓冲区大小、结构体和函数声明；不放现场可调默认值。

### 6.9 传感器上电 GPIO（预留）

当需要由软件控制**传感器供电**（如通过继电器或开关电路通断传感器电源）时，可使用“上电”寄存器驱动预留 GPIO。

**使用步骤：**

1. **启用 GPIO 驱动**  
   **当前版本已启用**，在 **USER/app_config.h** 中为：
   ```c
   #define SENSOR_POWER_GPIO_ENABLE   1
   ```
   为 **0** 时：上电寄存器（40014、40056、40098）仍可通过 Modbus 读写，但**不驱动**任何引脚。

2. **引脚定义**  
   在 **Core/Inc/main.h** 中已定义三路传感器使能继电器：
   - **JC1 / SENSOR_POWER0**：传感器 1（S1/ch0）→ **PC0**
   - **JC2 / SENSOR_POWER1**：传感器 2（S2/ch1）→ **PC13**
   - **JC3 / SENSOR_POWER2**：传感器 3（S3/ch2）→ **PB9**

3. **Modbus 控制**  
   - 写 **40014 = 1**：S1 使能 → JC1/PC0 输出高；写 **0** → 输出低。
   - 写 **40056 = 1**：S2 使能 → JC2/PC13 输出高；写 **0** → 输出低。
   - 写 **40098 = 1**：S3 使能 → JC3/PB9 输出高；写 **0** → 输出低。

4. **硬件接线**  
   **JC1/JC2/JC3** 默认按高电平有效处理：高电平为“使能/上电”，低电平为“关闭/断电”。若硬件为低电平有效，需在驱动层取反或修改 `modbus_slave.c` 中 `HAL_GPIO_WritePin` 的 SET/RESET 逻辑。

**说明**：上电后 `Register_Init()` 会把 S1/S2/S3 的 power_on 默认设为 1；当前已启用 GPIO，因此 JC1/JC2/JC3 会输出高。若希望上电时默认断电，需在 **NOx.c** 的 `Register_Init()` 中把对应 `g_tVar.S1.power_on` / `S2.power_on` / `S3.power_on` 改为 0，并在 `AfterFlash_Init()` 或初始化末尾调用 `Var_Write_SensorPowerOn(ch, 0)` 以同步输出到 GPIO。
